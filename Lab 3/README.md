# Лабораторна робота 3: Взаємодія (Sequence Diagram)
**Дисципліна:** Компоненти програмної інженерії  
**Проєкт:** OpenCRM — Динаміка взаємодії ключового бізнес-сценарію  

---

## 1. Мета роботи
Побудова та верифікація динамічної моделі взаємодії (Sequence Diagram) для ключового наскрізного бізнес-сценарію системи OpenCRM — **«Формування специфікації угоди, валідація товарів, розрахунок знижки та відправка комерційної пропозиції клієнту»** (наскрізна реалізація прецедентів `UC-2`, `UC-3`, `UC-4`, `UC-5`, `UC-6` із Лабораторної 2).

---

## 2. Учасники взаємодії (Participants) та архітектурні шари
* **Актор:**
  * `SalesManager`: ініціатор процесу формування та закриття угоди.
* **Рівень представлення (Presentation Layer):**
  * `DealController`: точка входу REST API (прийом та парсинг HTTP DTO).
* **Рівень бізнес-логіки (Domain Services):**
  * `DealService`: оркестратор бізнес-транзакції укладання угоди.
  * `PricingService`: спеціалізований доменний сервіс розрахунку сум, перевірки порогових значень та нарахування знижок.
* **Рівень доступу до даних (Persistence Repositories):**
  * `ProductRepository`: перевірка каталогу та отримання базової ціни `Product.base_price`.
  * `DealRepository`: атомарне збереження сутностей `DealItem` та оновлення `Deal.total_amount`.
* **Зовнішні системи (External Gateway):**
  * `EmailService`: зовнішній поштовий шлюз для надсилання комерційної пропозиції клієнту з обробкою мережевих збоїв.
