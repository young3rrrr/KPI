# Лабораторна робота 2: Вимоги та Use Cases
**Дисципліна:** Компоненти програмної інженерії  
**Проєкт:** OpenCRM — Специфікація вимог та модель прецедентів  

---

## 1. Мета роботи
Формалізація функціональних та нефункціональних вимог системи OpenCRM у трьох нотаціях (EARS, User Stories, Gherkin), побудова діаграми прецедентів (Use Case Diagram) із виділенням людських та системних акторів, побудова матриці трасування вимог типу $M:N$, а також аргументація усвідомлено непокритого функціоналу.

---

## 2. Актори системи
1. **Люди-актори:**
   * **`SalesManager` (Менеджер з продажів):** відповідає за обробку лідів, ведення клієнтів, укладання угод, додавання товарних позицій та планування взаємодій.
   * **`Admin` (Адміністратор):** відповідає за конфігурацію системи, управління каталогом продуктів та ролями користувачів (генералізація від `User`).
2. **Системні та фонові актори:**
   * **`EmailService` (Поштовий шлюз):** зовнішній сервіс, що забезпечує автоматизоване надсилання комерційних пропозицій та сповіщень клієнтам.
   * **`SchedulerService` (Cron-планувальник):** внутрішній фоновий сервіс, що здійснює періодичний моніторинг дедлайнів завдань та активностей (`Activity`).
